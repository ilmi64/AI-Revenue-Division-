# Funded Software Bounty Workflow

1. Discover an issue from a reputable project or bounty platform.
2. Verify the project owner, issue link, funding amount, currency, funding source, eligibility, and current open/unassigned status.
3. Read contribution rules, licence, security policy, acceptance criteria, and payout conditions.
4. Check whether another contributor has claimed or is actively solving it.
5. Estimate scope and testability; reject unclear, unsafe, or uneconomic work.
6. Prepare a proposed approach and risk/cost summary for owner approval before claiming or contacting maintainers.
7. After approval, implement in a branch, add tests, run checks, and document limitations.
8. Obtain approval before submitting a public claim or pull request.
9. Track review, acceptance, payment approval, and actual receipt separately.

Never assume a bounty is guaranteed income. Never pay a fee to claim or withdraw a bounty. Do not handle project secrets or production credentials.

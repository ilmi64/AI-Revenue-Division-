# First fixed-scope coding review commissioning

Limit the first real opportunity to one independently authorized inbound
request for review of a small code change. Prepare the offer and intake
privately. Quote one deliverable consisting of a human-reviewed patch
proposal, test evidence and explicit scope exclusions. Keep the service
out of live customer repositories and production accounts until the
owner approves that access and a data custody plan. Record zero upfront
cost and retain a separate billing approval.

| Step | Commissioning evidence required |
|---|---|
| Intake | Owner independently verifies customer identity, legal authority over the input, boundaries, recipient, fixed price and acceptance criteria. Retain the exact signed scope and input revision privately. The current scheduling fixture uses only synthetic requests. |
| Plan and delegate | Require one approved repository revision and a list of allowed files and tests. Use one authenticated company worker with local read access to the approved inputs and writes in a disposable workspace. Deny credentials, network, arbitrary customer scripts and work outside the statement of work. |
| Verify | Run approved deterministic checks under the isolated test boundary. Record input, command, toolchain, result, output digest and refusal reasons. An independent QA reviewer verifies scope and correctness and attests to the exact artifact. |
| Package | Recheck exact reviewed bytes through internal bundle acceptance. Keep customer material, pricing, review receipts and code private. Use the existing redacted OCC statuses for executive review. |
| Release and bill | Require Revenue owner approval of the exact artifact, recipient, delivery channel and amount. Retain a valid delivery-gate decision, a customer acceptance record and lawful invoice authorization. The current fixture remains on hold with delivery denied. |

Use the existing coding fixture end to end to rehearse these operator
steps. Native worker commissioning, customer contact, customer data
handling, live release and invoicing each need their own evidence and
authority. [Existing internal review workflow](revenue_bundle_acceptance.md)
